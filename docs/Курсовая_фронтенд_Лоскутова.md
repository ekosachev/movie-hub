## 1 Введение

### 1.1 Актуальность темы

Каталоги мультимедиа-контента в вебе остаются одним из основных способов навигации по большим наборам сущностей. Для конечного пользователя решающее значение имеет не только корректность серверных запросов, но и **интерфейс поиска** (текстовый запрос, фильтры, пагинация, обмен ссылками), а также **персонализация** в виде списков «избранное / просмотрено / план» и **пользовательских подборок (коллекций)**. Разработка таких частей на **React** с **TypeScript** позволяет снизить число ошибок за счёт статической типизации, а разделение на слои (`pages`, `components`, `api`, `playlists`, `routing`) — упростить сопровождение и поэтапную интеграцию с бэкендом.

### 1.2 Цель работы

Целью работы является **проектирование и реализация** на клиентской стороне следующих функциональных блоков приложения Movie Hub:

- поиск фильмов с **фильтрами** и **синхронизацией параметров с URL**;
- **профиль пользователя** с вкладками списков и коллекций;
- **системные списки** и **пользовательские коллекции** с режимом **offline-first** (localStorage) и последующей **интеграцией с REST API**;
- **разграничение доступа** на основе JWT и клиентского RBAC (в т.ч. сценарии контент-менеджера).

Интерфейсы аутентификации, онбординга, расширенная модалка фильма с полной серверной интеграцией комментариев/реакций и прочие блоки в командном проекте разрабатывались совместно с другими участниками; в отчёте они упоминаются лишь как контекст общей архитектуры.

### 1.3 Инструменты и методы

В работе применялись:

- язык **TypeScript**, UI-фреймворк **React 18** (функциональные компоненты, хуки);
- **React Router** v7 для маршрутизации;
- **Vite** как сборщик и dev-сервер;
- **Tailwind CSS** для стилизации;
- **JWT** (разбор payload на клиенте, массив `permissions`);
- **fetch** и собственная обёртка **`apiFetch`** с типизированным **`ApiError`**;
- **localStorage** для офлайн-хранения черновых данных плейлистов и сессии;
- **Git / GitHub** для версионирования и совместной разработки.

### 1.4 Объект и предмет исследования

**Объект** — процесс создания одностраничного веб-приложения (SPA), работающего с REST API и поддерживающего разные роли пользователей.

**Предмет** — методы организации состояния (контекст, локальное хранилище плейлистов, постепенная замена локальных данных данными сервера), синхронизации параметров поиска с адресной строкой и интеграции с эндпоинтами каталога и коллекций.

## 2 Задачи курсовой работы

В ходе работы были поставлены и решены следующие задачи:

1. Реализовать **поиск по каталогу** с передачей параметров на сервер (`/movies/search`), поддержкой **пагинации** (`limit`, `offset`, поле **`count`** как общее число результатов), а также **fallback** на локальные мок-данные при ошибке сети или неготовности ответа.
2. Обеспечить **синхронизацию строки поиска и фильтров с URL** (`q`, `tags`, `rating`, `yfrom`, `yto`, `page`), использовать **debounce** для уменьшения числа запросов при вводе.
3. Загрузить справочник тегов (**`GET /tags`**) и построить **отображение имя → id** для отправки **`tag_ids`** на сервер; до загрузки справочника допускать **клиентскую** фильтрацию по именам тегов в ограниченном режиме.
4. Реализовать **профиль** (`ProfilePage`): вкладки системных списков и коллекций, условное отображение вкладки контент-менеджера по правам JWT.
5. Разработать модуль **`usePlaylists`**: локальное состояние списков и коллекций, сохранение в **localStorage**, при наличии токена — **загрузка системных списков** и **моих коллекций** с сервера, слияние с локальными записями.
6. Реализовать **оптимистичное** добавление/удаление фильма в системных списках и коллекциях с **откатом** при ошибке API.
7. Подключить **CRUD коллекций** и **добавление/удаление фильма в коллекции** к REST API (`/collections`, `/me/collections`, `/collections/:id/movies`).
8. Унифицировать разбор ошибок API: поддержка поля **`error`** в JSON в дополнение к **`message`**.

## 3 Архитектура клиентской части

### 3.1 Компонентная структура

Приложение разбито на слои:

| Слой | Назначение | Примеры |
|------|------------|---------|
| `pages` | Экранные сценарии | `HomePage`, `ProfilePage`, `CollectionPage`, `MovieCreatePage` |
| `components` | Переиспользуемые блоки | `Header`, `FilterPanel`, `MovieCard`, модальные окна |
| `api` | Доступ к REST | `movieSearch.ts`, `collections.ts`, `userLists.ts`, `http.ts` |
| `playlists` | Локальное состояние списков/коллекций | `storage.ts`, `usePlaylists.ts`, `types.ts` |
| `routing` | Ограничение доступа к маршрутам | `RequireAuth`, `RequirePermission`, `RequireAnyPermission` |
| `auth` | Разбор JWT | `jwt.ts` |

Такое разделение позволило сначала отработать UX на локальных данных, затем подключать сервер без переписывания страниц.

### 3.2 Глобальный контекст

Состояние сессии инкапсулировано в **`AuthProvider`**: хранятся email, токен, идентификатор пользователя (`sub` из JWT), массив **`permissions`**, вычисленная роль. Хук **`useAuth`** предоставляет **`hasPermission(permission)`** для условного рендеринга.

### 3.3 Роутинг

Корневой компонент **`App`** задаёт маршруты. Часть страниц обёрнута в **`GlobalLayout`** с шапкой и строкой поиска. Параметр **`q`** обновляется с **debounce** (250 мс), чтобы не спамить историю браузера и не перегружать сервер. Профиль и страница коллекции защищены **`RequireAuth`**. Создание фильма — **`RequirePermission`** (`update_movies`).

## 4 Поиск и фильтры

### 4.1 URL и состояние

Фильтры и страница пагинации хранятся в query-параметрах. При смене текста поиска или набора фильтров номер страницы сбрасывается на первый (через `useSearchParams`), что соответствует ожидаемому UX каталога.

### 4.2 Запрос `searchMovies`

Функция **`searchMovies`** собирает строку запроса: `title`, `min_rating`, `date_from`, `date_to`, повторяющиеся `tag_ids`, `limit`, `offset`. Поддерживаются два формата ответа сервера: объект с **`items`**, **`count`**, **`offset`**, и устаревший массив — для переходного периода. Поле **`count`** интерпретируется как **общее число** записей по запросу (total), а не длина текущей страницы.

### 4.3 Отмена запросов

Для поиска используется **`AbortController`**: при быстрой смене параметров предыдущий запрос отменяется, что исключает гонки и отображение устаревших результатов.

## 5 Профиль

Страница **`ProfilePage`** отображает системные вкладки (избранное, просмотрено, буду смотреть), список коллекций с переходом на **`/collection/:id`**, а также вкладку контент-менеджера при наличии права **`update_movies`**; плашка роли **Administrator** показывается пользователям с соответствующим набором прав в JWT. Создание коллекции выполняется через модальное окно; при наличии токена создание уходит на **`POST /collections`**, при ошибке возможен откат к локальному созданию.

## 6 Списки и коллекции

### 6.1 Offline-first

Данные списков и коллекций сериализуются в **localStorage** с ключом, зависящим от пользователя (по email). Это обеспечивает работу интерфейса без бэкенда и служит буфером при ошибках сети.

### 6.2 Системные списки на API

После авторизации выполняется **`GET /collections/me`**, возвращающий три массива идентификаторов фильмов. Переключение фильма в списке в модальном окне реализовано **оптимистично**: сначала меняется локальное состояние, затем **`POST /collections/me/:list`** или **`DELETE .../:movieId`**; при ошибке выполняется откат.

### 6.3 Коллекции

Выполняются **`GET /me/collections`**, **`POST/PATCH/DELETE /collections`**, **`POST/DELETE /collections/:id/movies`**. Описание коллекции в UI может храниться только локально, если сервер не поддерживает поле description — при слиянии с ответом сервера текст подтягивается из предыдущего локального состояния по `id`.

---

## 7 RBAC

Сервер выдаёт список строковых прав в JWT. Клиент **не заменяет** серверную проверку, но скрывает недоступные действия и блокирует маршруты. Роли **`admin`** / **`content_manager`** выводятся эвристически из набора прав в **`roleFromPermissions`** (с учётом актуальных имён с сервера и legacy-имён в старых токенах). Для маршрутов, где допустимо несколько альтернативных прав, в проекте может использоваться компонент **`RequireAnyPermission`** (например, при расширении сценариев после согласования с бэкендом).

---

## 8 API

Базовый URL задаётся **`VITE_API_BASE_URL`** с запасным значением `http://localhost:8080/api/v1`. Обёртка **`apiFetch`** добавляет JSON-тело, заголовок **`Authorization`**, обрабатывает **204**, извлекает текст ошибки из **`error`** или **`message`**.

Модуль **`userLists`** инкапсулирует системные списки. Модуль **`collections`** — коллекции и фильмы внутри них. Модуль **`movieSearch`** — поиск каталога (частично через относительный путь `/api/v1/...` в соответствии с настройкой прокси Vite).

## Приложение А

**Листинг А.1 — Интерфейс и провайдер аутентификации (`front/src/context/AuthContext.tsx`, фрагмент)**

```typescript
export interface AuthUser {
  email: string;
  token: string;
  id: number | null;
  permissions: string[];
  role: AppRole;
}

interface AuthContextType {
  user: AuthUser | null;
  login: (email: string, token: string) => void;
  logout: () => void;
  hasPermission: (permission: string) => boolean;
}

export const AuthProvider: React.FC<{ children: React.ReactNode }> = ({ children }) => {
  const [user, setUser] = useState<AuthUser | null>(() => {
    const token = localStorage.getItem('token');
    const email = localStorage.getItem('userEmail');
    if (!token || !email) return null;

    const payload = parseJwt(token);
    const permissions = payload?.permissions ?? [];
    const id = userIdFromSub(payload?.sub);
    const role = roleFromPermissions(permissions);

    return { email, token, id, permissions, role };
  });

  const login = (email: string, token: string) => {
    const payload = parseJwt(token);
    const permissions = payload?.permissions ?? [];
    const id = userIdFromSub(payload?.sub);
    const role = roleFromPermissions(permissions);

    localStorage.setItem('token', token);
    localStorage.setItem('userEmail', email);
    setUser({ email, token, id, permissions, role });
  };

  const logout = () => {
    localStorage.removeItem('token');
    localStorage.removeItem('userEmail');
    setUser(null);
  };

  const hasPermission = (permission: string): boolean => {
    return user?.permissions.includes(permission) ?? false;
  };

  const value = useMemo(() => ({ user, login, logout, hasPermission }), [user]);

  return (
    <AuthContext.Provider value={value}>
      {children}
    </AuthContext.Provider>
  );
};
```

const App: React.FC = () => {
  const [searchParams, setSearchParams] = useSearchParams();
  const qFromUrl = searchParams.get('q') ?? '';

  const [searchDraft, setSearchDraft] = useState(qFromUrl);
  useEffect(() => setSearchDraft(qFromUrl), [qFromUrl]);

  const debouncedDraft = useDebouncedValue(searchDraft, 250);

  useEffect(() => {
    setSearchParams(prev => {
      const next = new URLSearchParams(prev);
      const trimmed = debouncedDraft.trim();
      if (trimmed) next.set('q', trimmed);
      else next.delete('q');
      return next;
    }, { replace: true });
  }, [debouncedDraft, setSearchParams]);

  const setSearchQuery = useMemo(() => {
    return (val: string) => setSearchDraft(val);
  }, []);

  return (
    <Routes>
      <Route path="/auth" element={<AuthPage />} />
      <Route path="/onboarding" element={<OnboardingPage />} />

      <Route element={<GlobalLayout searchQuery={searchDraft} setSearchQuery={setSearchQuery} />}>

        <Route path="/profile" element={<RequireAuth><ProfilePage /></RequireAuth>} />
        <Route path="/collection/:id" element={<RequireAuth><CollectionPage /></RequireAuth>} />
        <Route path="/movies/new" element={
          <RequirePermission permission="update_movies">
            <MovieCreatePage />
          </RequirePermission>
        } />
      </Route>
    </Routes>
  );
};

**Листинг Б.2 — Хук дебаунса (`front/src/utils/useDebouncedValue.ts`)**

```typescript
export function useDebouncedValue<T>(value: T, delayMs: number) {
  const [debounced, setDebounced] = useState(value);

  useEffect(() => {
    const id = window.setTimeout(() => setDebounced(value), delayMs);
    return () => window.clearTimeout(id);
  }, [value, delayMs]);

  return debounced;
}
```

**Листинг В.2 — Модуль поиска (`front/src/api/movieSearch.ts`)**

```typescript
export async function searchMovies(params: {
  title?: string;
  minRating?: number;
  dateFrom?: string;
  dateTo?: string;
  tagIds?: number[];
  limit: number;
  offset: number;
  signal?: AbortSignal;
}): Promise<{ items: MovieSearchItem[]; count: number; offset: number }> {
  const sp = new URLSearchParams();
  if (params.title) sp.set('title', params.title);
  if (params.minRating && params.minRating > 0) sp.set('min_rating', String(params.minRating));
  if (params.dateFrom) sp.set('date_from', params.dateFrom);
  if (params.dateTo) sp.set('date_to', params.dateTo);
  for (const id of params.tagIds ?? []) sp.append('tag_ids', String(id));
  sp.set('limit', String(params.limit));
  sp.set('offset', String(params.offset));

  const res = await fetch(`/api/v1/movies/search?${sp.toString()}`, { signal: params.signal });
  const json: ApiResponse<MovieSearchDataV2 | MovieSearchItem[]> = await res.json();

  if (!res.ok || !json.success) {
    throw new Error(json.error || 'Movie search failed');
  }

  const data = json.data;
  if (!data) return { items: [], count: 0, offset: params.offset };

  if (!Array.isArray(data) && Array.isArray((data as MovieSearchDataV2).items)) {
    const v2 = data as MovieSearchDataV2;
    return { items: v2.items, count: v2.count ?? v2.items.length, offset: v2.offset ?? params.offset };
  }

  const items = data as MovieSearchItem[];
  return { items, count: items.length, offset: params.offset };
}
```

      const prevCol = prev.collections.find(c => c.id === r.id);
      return {
        id: r.id,
        title: r.name,
        description: prevCol?.description ?? '',
        isPublic: r.is_public,
        movieIds: (r.movie_ids ?? []).map(Number),
        createdAt: prevCol?.createdAt ?? new Date().toISOString(),
      };
    });
    const localsOnly = prev.collections.filter(c => !backendIds.has(c.id));
    return { ...prev, collections: [...mergedFromServer, ...localsOnly] };
  });
});

toggleInList: (list, movieId) => {
  const token = user?.token;
  if (!token) {
    setState(prev => toggleMovieInList(prev, list, movieId));
    return;
  }
  const wasInList = state.lists[list].includes(movieId);
  setState(prev => toggleMovieInList(prev, list, movieId));
  (wasInList
    ? removeMovieFromSystemList(token, list, movieId)
    : addMovieToSystemList(token, list, movieId)
  ).catch(() => {
    setState(prev => toggleMovieInList(prev, list, movieId));
  });
},

export function roleFromPermissions(permissions: string[] | undefined): AppRole {
  const set = new Set(permissions ?? []);
  if (
    set.has('delete_users') ||
    set.has('manage_comments') ||
    set.has('ban_users') ||
    set.has('remove_comments')
  ) {
    return 'admin';
  }
  if (set.has('create_movies') || set.has('update_movies')) return 'content_manager';
  return 'user';
}

  permissions,
  children,
}: {
  permissions: string[];
  children: React.ReactNode;
}) {
  const { user, hasPermission } = useAuth();
  const location = useLocation();

  if (!user) {
    return <Navigate to="/auth" replace state={{ from: location }} />;

  if (!permissions.some(p => hasPermission(p))) {
    return <Navigate to="/profile" replace />;
